INGInious API
==============

This page is dedicated to the RESTful API of INGInious. It is intended for developers to access INGInious features outside of the UI.

If you are looking for the runfile API, learn more about it the :ref:`runfile introduction.<run_file_api>`

Using the API
-------------
Multiple endpoints are available to interact with INGInious. The API is RESTful and uses session or token authentication.
In the following sections, we will explain how to use the API and how to authenticate.

Available endpoints
`````````````````
The current API allows :

- Checking available authentication methods, authentication through session and checking if the session is valid
- Listing courses, and their informations, available to the authenticated client
- Listing tasks, and their informations, available to the authenticated client
- Listing all the submissions that the authenticated client made for a specific course or task

For more information about the available endpoints, please refer to the :ref:`API documentation.<rest_api_documentation>`.

Authentication through session
```````````````````````````````
Using the API with the flask session will need the use of the authentication endpoint.
The following example shows how to authenticate with /api/v0/authentication endpoint.
You can check if the session is valid by sending a GET request to the same endpoint.

::

    curl -c api_cookies.txt -X POST "http://localhost:8080/api/v0/authentication" -d "login=myusername&password=mypassword"
    curl -b api_cookies.txt -X GET "http://localhost:8080/api/v0/authentication"


Using the other endpoints is done in the same way each time. Here are a few examples :

::

    curl -b api_cookies.txt -X GET "http://localhost:8080/api/v0/courses/tutorial"
    curl -b api_cookies.txt -X GET "http://localhost:8080/api/v0/courses/tutorial/tasks/01_getting_started/submissions"

    curl -b api_cookies.txt -X POST "http://localhost:8080/api/v0/courses/tutorial/tasks/01_getting_started/submissions" \
    -d "thecode=test"

    curl -b api_cookies.txt -X POST "http://localhost:8080/api/v0/courses/tutorial/tasks/05_fetching_input/submissions" \
    -F "studentupload=@/path/to/file/my_file.txt" -F "studentcode=some_code" -F "thecode=some_other_code"


Authentication through a token
```````````````````````````````

Authentication through a token does not require the use of the authentication endpoint.
It is also safer because is generated by the user in the UI and can be revoked at any time.

To create a token, connect to your profile in the webapp and go tou your user preferences.
A page is available to manage your tokens. You can give descriptions to them as well as expiration dates.

Here are a couple examples of how to use the API with a token and with a json format for inputs.
When sending values in a json format, files must be sent as base64 encoded strings. You can of course use JSON format
with sessions and the other way around.

::

    curl -X GET "http://localhost:8080/api/v0/courses/tutorial/tasks/01_getting_started/submissions" \
        -H "Authorization: Bearer <your_token>"

    curl -X POST "http://localhost:8080/api/v0/courses/tutorial/tasks/01_getting_started/submissions" \
        -H "Authorization: Bearer <your_token>" \
        -H "Content-Type: application/json"  \
        -d '{ "thecode" : "test"}'

    curl -X POST "http://localhost:8080/api/v0/courses/tutorial/tasks/05_fetching_input/submissions" \
        -H "Authorization: Bearer <your_token>" \
        -H "Content-Type: application/json"  \
        -d '{ "studentupload" : {"filename" : "my_file.txt" , "value" :  "<base_64_encoded>"}, "studentcode" : "some_code", "thecode" : "some_other_code"}'
